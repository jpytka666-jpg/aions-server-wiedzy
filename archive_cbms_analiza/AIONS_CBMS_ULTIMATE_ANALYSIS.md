## 🔬 TECHNICAL DEEP-DIVE

### **CBMS (Code Book Memory System) - Core Concept**

**From**: `cbms objasnienie.txt`

**Key Insight**: CBMS kompresuje gigantyczną wiedzę do "książki kodów" (code-book):
- Nie upychasz całej wiedzy w parametrach modelu
- Budujesz krótkie klucze/etykiety → adresują małe fragmenty wiedzy (chunki)
- "Kilka linijek kodu" to graf pudełek (BOX-y) + manifesty

**4 Warstwy Kompresji:**

1. **Semantyczna** - Dzielisz wiedzę na chunki z ID, konceptem i referencjami
2. **Obliczeniowa** - SoftRetrieval + GatedMix + KVRead: wybierasz 12 najtrafniejszych kawałków
3. **Parametryczna** - Wagi i indeksy kompresujesz (int8/int4/NF4, PQ)
4. **Interfejsowa** - Graf BOX-ów + manifesty w JSON

**Dlaczego To Działa:**
- Świat ma ogromną redundancję
- CBMS wydziela wzorce do słownika (code-book)
- Zamiast "model pamięta cały internet", masz "model wie, jak znaleźć i złożyć właściwe 0.01% na żądanie"

## 🔍 DETAILED TECHNICAL ANALYSIS

### **1. Hangul Addressing System**

**Purpose**: Korean syllable-based memory addressing for semantic compression

**Implementation** (`server/hangul_addressing.py`, `server/korean_keys.py`):
```python
# Encoding: (initial, medial, final) → Korean syllable

- Pronunciation mapping
- Checksum verification
```

**Benefits:**
- Semantic clustering via syllable similarity
- Efficient memory addressing
- Cultural/linguistic grounding
- Collision-resistant hashing

### **2. CRLA (Coordinate Retrieval Learning Architecture)**

**Purpose**: Tournament-based chunk selection for optimal knowledge retrieval

**Algorithm** (`server/crla_core.py`):
1. Query → Korean key generation
2. Bucket selection via Hangul addressing
3. Tournament among N candidates (default: 8)
4. Top-K chunks selected (default: 12)
5. Soft attention weighting
6. Response generation with citations

**Metrics:**
- Coverage: % of query terms found in chunks
- Precision: Relevance of retrieved chunks
- Orthogonality: Diversity of selected chunks
- Entropy: Information content distribution

### **3. Anti-Hopfield Memory**

**Purpose**: Differentiable memory retrieval without catastrophic forgetting

**Key Differences from Hopfield Networks:**
- No fixed-point attractors (prevents mode collapse)
- Soft retrieval with attention weights
- Gradient-friendly operations
- Orthogonality loss for diversity

**Implementation:**
```python
# Soft retrieval with temperature
attention = softmax(query @ keys.T / temperature)
retrieved = attention @ values

# Orthogonality loss
ortho_loss = mean((keys @ keys.T - I)^2)
```

### **4. Coordinate Computing**

**Purpose**: Observer-driven parallelization for compute efficiency

**Concept:**
- 6D space divided into charts (coordinate patches)
- Observer position determines active charts
- Only compute in observer's "light cone"
- Halo exchange for boundary conditions

**Savings:**
- 71.9% compute reduction (18/64 active charts)
- Parallel execution across active regions
- Dynamic load balancing
- Scalable to arbitrary dimensions
